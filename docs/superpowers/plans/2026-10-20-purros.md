# PurrOS Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A QEMU VM that boots Alpine straight into the PurrOS screen, where plain words and Windows, Linux or Mac commands all work, pictures come from klein, and a pixel cat acts out what is happening.

**Architecture:** purrd (Python, aiohttp) inside the VM serves one page and a WebSocket. A router turns each line into an Intent (PurrOS word, phrasebook action, real shell command, or brain question); actions emit protocol messages the page renders inline. Chromium in a cage kiosk shows the page. On the host, purr-host renders pictures through Jarvis's mockup.py, and Ollama is the brain.

**Tech Stack:** Python 3.12 + aiohttp 3.x (stdlib unittest), vanilla JS + canvas, xterm.js, Alpine 3.24, cage, Chromium, QEMU/KVM in WSL2.

**Spec:** docs/superpowers/specs/2026-10-20-purros-design.md

## Global Constraints

- purrd listens on 127.0.0.1:7777 only; purr-host on 127.0.0.1:7790 only. Nothing binds 0.0.0.0.
- Brain default: kind `ollama`, url `http://10.0.2.2:11434`, model `jarvis-ornith-ctx131072`, thinking off.
- Pictures default: kind `purr-host`, url `http://10.0.2.2:7790`, quality `careful` (mockup.py quality mode); `quick` = `--quality fast`.
- Delete never calls rm: it moves to `~/.local/share/Trash/files`. "empty trash" asks first.
- Messages are lowercase, short and dry, like the mockup: "dir is the windows way. same list:".
- No dashes as punctuation in any user-facing copy.
- Nothing loads from the internet at run time; fonts and xterm.js live in `app/static/vendor/` (fetched by `app/fetch-vendor.sh`).
- Moods and status words exactly as the spec's table; nap after `nap_seconds` (default 45).
- No Claude, Anthropic or AI attribution in commits; one-line commit messages.

## Review Focus

1. File names with spaces, capitals or no extension ("open My Notes", "open cabin"): match case-insensitively and by stem before giving up.
2. The brain is down or slow (game gate killed Ollama, cold load 25 s): phrasebook still works, the cat goes oops with "my brain is napping", never a hang.
3. A command that never ends or floods output (`yes`, `ping` without -c, `cat /dev/urandom`): output capped, Ctrl+C stops it, a 60 s cap for non-interactive commands.
4. Destructive input in any dialect (`del *.*`, `rm -rf ~`, `Remove-Item -Recurse`, `format c:`): goes to Trash or asks, never deletes outright.
5. Brain JSON that is malformed or proposes a risky command: parsed leniently, risky commands shown with yes/no, garbage shown as plain text.

## File structure

```
app/purrd/fsutil.py      find, suggest, kind, listdir, pretty paths
app/purrd/safety.py      classify(cmd) -> read | change | danger
app/purrd/router.py      route(text) -> Intent; the phrasebook tables live here
app/purrd/actions.py     do(intent, ctx): built-in actions, emits protocol messages
app/purrd/shell.py       run(cmd) streaming; Pty sessions; is_interactive
app/purrd/brain.py       ask(text, info, cfg) for ollama and openai kinds
app/purrd/pictures.py    draw(prompt, cfg) -> png bytes; save_picture
app/purrd/settings.py    load, save, patch with validation
app/purrd/server.py      aiohttp app: /, /static, /file, /health, /ws session
app/static/index.html    the screen
app/static/purr.css      themes, glow, layout (ported from the mockup)
app/static/cat.js        sprite painter and the PurrOS cat (ported)
app/static/purr.js       input line, WebSocket client, renderers, settings panel, xterm panes
app/fetch-vendor.sh      VT323, IBM Plex Mono, xterm.js into static/vendor
app/tests/test_*.py      unittest suites
host/purr-host.py        POST /draw -> mockup.py --managed -> PNG
host/purros, vm/*        launcher and image build (VM task)
```

## Protocol (purr.js <-> server.py)

Client to server: `{t:"run", id, text}`, `{t:"stop"}`, `{t:"confirm", id, yes}`, `{t:"term_in", sid, data}`, `{t:"term_resize", sid, cols, rows}`, `{t:"settings", patch}`, `{t:"complete", id, text}`.

Server to client: `{t:"hello", settings, cwd, name}`, `{t:"mood", mood, word}`, `{t:"line", text, cls}` (cls: "", "dim", "hi", "ran"), `{t:"list", items:[{name, dir, kind, path}], summary}`, `{t:"out", text}`, `{t:"media", kind, name, path, url}` (kind image, video, audio, pdf), `{t:"text", name, lines}`, `{t:"ask", id, question, cmd}`, `{t:"progress", text}`, `{t:"term_open", sid, title}`, `{t:"term_out", sid, data}`, `{t:"term_exit", sid}`, `{t:"cwd", cwd}`, `{t:"settings", settings}`, `{t:"clear"}`, `{t:"completions", id, items}`, `{t:"end", id}`.
